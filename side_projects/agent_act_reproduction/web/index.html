02 / ARCHITECTURE

一句话经过哪些模块，才变成机械臂动作？

这里没有开放式规划器。整条链路是有边界、可逐段检查的。

  1. 01 自然语言命令 “把瓶子放到架子上”
  2. 02 Agent / MockAgent 理解有限关键词
  3. 03 选择预定义任务 place_bottle_on_shelf
  4. 04 Policy Router 找到 Bottle checkpoint
  5. 05 对应 ACT policy 输出动作 chunks
  6. 06 Panda 控制接口 笛卡尔目标 + 夹爪
  7. 07 MuJoCo 执行 真实接触与动力学
  8. 08 任务成功判定 位置、释放、稳定性

需要抓住的四个事实

  • Agent 很薄：主要把语言映射到系统已经拥有的任务名称。
  • 动作来自 ACT：真正控制抓取、搬运、释放的是 task-specific policy。
  • 一项任务一个 policy：Bottle、Tissue、Draw 第一版分别训练，不共享“通用技能”。
  • 失败应诚实返回：没有对应 capability 时，系统返回 CANNOT_EXECUTE。

自然语言只是入口，不会凭空创造新的机械臂能力。

03 / ESSENCE

这个系统的本质

它做了什么

把三层工程接口接通

  • 用自然语言选择一个已有 capability
  • 路由到这个任务专用的 ACT checkpoint
  • 把 learned action 交给 Panda 控制器执行
  • 用物理条件判断任务是否真的成功
它没有做什么

没有解决开放世界机器人问题

  • 不会自动学会从未训练过的新任务
  • 没有通用视觉理解或物体检测
  • 没有开放式长程规划和自主纠错
  • 没有证明真实世界部署的鲁棒性

更准确的名字是：语言接口 + policy 路由 + 固定任务 motor skill， 而不是开放世界通用操作系统。

04 / DIFFICULTY

实现难度如何？

难度不是均匀分布的。语言路由很轻，可靠接触、数据采集和跨场景泛化更难。

模块 定性难度 主要工作
Mock Agent / 任务路由 低 关键词或 structured output，映射到有限技能表
MuJoCo 场景搭建 低到中 模型、接触参数、物体重置、成功判据
Scripted expert 采 demonstration 中 让轨迹在扰动下持续成功，并保证数据顺序正确
ACT 训练与推理接入 中 chunk 数据、归一化、checkpoint、纯 policy rollout
三个固定 Demo 在仿真中跑通 中到高 逐任务调接触、采数据、训练、定位失败模式
真机部署 高 标定、安全、时延、硬件误差、sim-to-real 差异
开放场景泛化 / 通用 manipulation 高 感知、数据规模、新任务、失败恢复与长程规划
客观结论

固定场景下的仿真 Demo 复现，更多是中等难度的工程集成； 如果上真机、加入视觉感知或要求跨场景泛化，难度会显著提高。

05 / PERCEPTION

为什么外行会觉得它很强？

“你说一句，它就真的动手做了。”

自然语言与机械臂动作连在一起，展示效果天然很强。观众看到的是完整行为， 很容易把“选择已有技能”理解成“理解任意要求并现场想出办法”。

但底层通常只是从少数预定义技能中选出一个，再运行对应的 task-specific policy。 展示是真实的，能力范围也同样真实而有限。

06 / BOUNDARY

能力边界：这个 Demo 能证明什么？

能

它能说明什么

  • 固定场景下可以整合语言接口与 policy execution
  • ACT 能承担完整的单任务 learned motor execution
  • 对训练范围内的小扰动可以有一定鲁棒性
  • 成功判定可以基于物理结果，而不是“程序没报错”
  • 这种 Hackathon 架构可以清晰、低成本地复现
不能

它不能说明什么

  • 不代表拥有通用操作能力
  • 不代表能自动完成训练中没有的新任务
  • 不代表能在开放环境中稳定泛化
  • 不代表已解决真实世界鲁棒部署
  • 不代表拥有复杂长程规划与自主恢复能力
训练中心附近 20 / 20 nominal
训练范围内 20 / 20 ±1 cm
范围外探测 11 / 20 ±3 cm OOD

扰动从 ±1 cm 增加到 ±3 cm 后，成功率从 100% 降至 55%。 这正是“固定分布 motor policy”而非通用智能的直观证据。

07 / CONCLUSION

不神秘，但值得拆开看清楚

如果只看固定工作区、预定义任务、仿真环境下的三个 Demo，这种 Agent + ACT 系统并不神秘， 更接近一个清晰可复现的工程集成方案。它的价值主要在于把语言接口、模仿学习 policy 和机器人 执行链条打通；但它的能力边界也很明确。
